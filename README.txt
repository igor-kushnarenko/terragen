Редактор ландшафта — версия 0.22.0

Естественные берега при создании мира:
- Для территории меньше полной карты все биомы используют общий береговой
  контур: заливы, полуострова и отдельные прибрежные островки вместо круга.
- Архипелаги и фьорды сохраняют собственные проливы и характер рельефа.
  Озёра джунглей и тайги располагаются внутри суши. Реки продолжаются до моря,
  при перепаде высоты образуя водопад; устье не создаёт дамбу поперёк залива.
- Очертания зависят от сида и совпадают в эскизе и готовом мире.
  Мелкие островки лучше видны при более высоком разрешении рельефа.
- Сохранённые миры не меняются. Чтобы увидеть новые берега, создайте мир
  заново; тот же сид теперь даст обновлённую береговую линию.
- Проверка: npm test, npm run build.

Вода и устья рек:
- Водопады рисуются несколькими слоями подвижных струй; у основания
  добавлены брызги, водяная дымка и расходящаяся пена. Морское продолжение
  устья использует поверхность моря без отдельной прямоугольной полосы.
- Эти визуальные эффекты работают и в сохранённых мирах с профилем устья.
  Количество частиц зависит от качества графики; вдали эффекты скрываются.
- Убрана регулярная клетчатая каустика на море, озёрах и реках.
  Световые узоры на мелководье теперь имеют нерегулярную движущуюся форму.
- В новых прибрежных мирах реки джунглей и тайги доходят до моря.
  Небольшой перепад даёт пологий выход, большой — падающий поток с пеной.
- Профиль устья сохраняется в проекте и при настройке прозрачности и волн.
  Для обновления русел старого сгенерированного мира создайте мир заново.

Биом Тайга:
- Мир → Создать → Тайга: еловая, сосновая, лиственничная, заболоченная и зимняя.
- Объекты → Тайга · северный лес: состав, плотность, подрост, мхи, лишайники,
  валежник, валуны, влажность, прогалины, дымка, сезон и снежный покров.
- Локальные области тайги, процедурные хвойные с тремя LOD, ручьи и торфяные
  озерца, сезонные материалы. По умолчанию летний лес без снега.
- Настройки входят в проект, автосохранение и историю изменений.
- Примеры examples/taiga-*.json; проверка npm run verify:taiga.
  Возможности и ограничения: docs/TAIGA.md.

Исправление текстур импортированных GLB:
- Добавлена совместимость с KHR_materials_pbrSpecularGlossiness: цветовые
  карты, отражения, нормали и блеск старых glTF-моделей корректно загружаются.
- Самодостаточный GLB хранится без перекодирования изображений. Исходный файл
  не раздувается при импорте; параметры нормализации хранятся отдельно.
- Чтобы исправить ранее импортированную белую модель: Объекты → Библиотека
  моделей → выберите её → «Заменить выбранную модель из файла» → исходный GLB.
  Положение, масштаб и настройки экземпляров сохраняются; замена отменяется.
- Подробности и проверка: docs/GLB_TEXTURES.md.

Скелетные GLB и анимации в 0.22:
- Объекты → Библиотека моделей → Импорт GLB / glTF. Кости и клипы
  определяются автоматически; исходная иерархия и привязки скелета сохраняются.
  Нажмите «Разместить выбранную модель» — первый клип начнёт воспроизводиться.
- Выберите объект в сцене или в «Выбор и трансформация»: блок «Анимация модели»
  позволяет выбрать клип или исходную позу, включить паузу, изменить скорость,
  повтор, перейти в начало и установить позицию в клипе. Копии независимы.
- Поддерживаются также анимации узлов, morph targets и скелеты без клипов.
  Настройки участвуют в истории, автосохранении и переносимом проекте .terrain.
  Статические модели сохраняют прежний инстансинг; форматы проектов 1–11 открываются.
- До 128 анимированных экземпляров, 512 костей и 128 клипов на модель.
  Прежние лимиты 64 МБ на модель и 512 МБ на мир сохранены. Скелетные модели
  импортируются высотой 1,8 м; размер меняется обычным инструментом масштаба.
  По умолчанию их коллизии отключены; анимация не управляет физикой персонажа.
- Локальный пример: examples/animated-rig.glb. Проверка: npm test,
  npm run build, npm run verify:animation. Подробности: docs/ANIMATED_GLB.md.

Тропические джунгли в 0.21:
- Мир → Джунгли: густые, речные или с поляной. У вариантов общий генератор,
  сид, мягкие холмы, микрорельеф, влажные низины и редкие замшелые валуны.
  Ручей/река и лесной водоём создаются вместе с вырезанным руслом.
- Четыре яруса: редкие гиганты, сомкнутый полог двух видов, молодые деревья,
  пальмы, бананы, древовидные папоротники и почвенный покров с грибами.
  Лианы, эпифиты и цветы размещены на ветвях деревьев; есть гниющие стволы.
- Объекты → Тропические джунгли: полог, гиганты, подлесок, лианы, влажность,
  просветы и отключаемая дымка. Изменение атмосферы не пересоздаёт растения.
  Микрорельеф и водоёмы задаются при создании нового мира.
- Ландшафт → Биомы: локальные «Джунгли» с выбором варианта. Их растения
  можно обновить отдельно, сохранив объекты за пределами выбранной области.
- Почва смешивает существующие PBR-слои земли, листовой подстилки, мха,
  мокрых камней и грязи. Подлесок редеет под кронами и усиливается у воды.
- Три LOD, инстансинг, отсечение чанков и ближний почвенный покров сохраняют
  бюджет сцены. Параметры и растения сохраняются в проекте формата 11;
  старые миры открываются без автоматической перегенерации.
- Проверка: npm test, npm run build, npm run verify:jungle.
  Примеры: examples/jungle-dense.json, jungle-river.json, jungle-clearing.json.
  Описание и измерения: docs/JUNGLE_BIOME.md.

Новый интерфейс GenTerrain:
- Четыре рабочих пространства сверху: Мир, Ландшафт, Окружение, Объекты.
- Справа показываются параметры одного выбранного инструмента; кисти — слева.
- Ctrl+K — поиск инструмента; Ctrl+S — сохранить мир в библиотеке.
- «Экспорт» — переносимый .terrain, импорт проектов, карта высот и OBJ.
- «Мир → Мои миры» — библиотека. Эрозия, биомы и композиция — в «Ландшафт».
- Кнопка «Параметры» сворачивает инспектор и расширяет рабочую сцену.
- Настройки графики и камеры доступны по кнопке с ползунками сверху.
- В прогулке панель редактора открывается по E; пространство можно сменить
  в списке над параметрами. P возвращает в обычный редактор.
- Исследование, карта навигации и проверка: docs/UI_REDESIGN.md.


Воздушный шар в 0.20:
- Прогулка → «Сценарии» → «Воздушный шар» → «Подготовить шар».
  Площадка проверяется по воде, уклону и свободному месту для всей оболочки.
  Можно выбрать площадку на карте; «К площадке» переносит к подготовленной корзине.
- Подойдите к корзине и смотрите на неё: B — сесть. Отпустите швартовку.
  Горелка нагревает воздух постепенно; горизонтально шар следует ветру.
- Пробел — нагрев, V — верхний клапан, стрелки вверх/вниз — мощность,
  Z — сброс 5 кг балласта, X — выпуск/подъём якоря, C — камера.
  U открывает панель пилота во время полёта и освобождает мышь.
  Клик по сцене возвращает обзор мышью; Esc — пауза, E — редактор.
  Клавиши переназначаются в «Параметры полёта и клавиши».
- Приборы: температура, высота, скорость, ветер и его слои, топливо,
  балласт, длина/натяжение троса, энергия лебёдки и масса.
  Пейзажный режим допускает помощника высоты и бесконечные ресурсы;
  ручной учитывает повреждение оболочки и разрыв перегруженного троса.
- Якорь имеет массу, контакт с грунтом, ограниченную прочность троса,
  тягу и энергию лебёдки. Висящий в воздухе якорь не закрепляет шар.
- Выйти можно после остановки на поверхности. «Вернуться к старту»
  завершает полёт и освобождает аппарат. Запасы пополняются у старта.
- Физика Rapier работает в общем мире с шагом 1/120 с. Три тела,
  четыре ограничения подвески и не более 96 ближайших коллайдеров крон.
  Модель, тёплый свет и шум горелки работают с локальными ресурсами.
- Формат документа 11 хранит полёт вместе с миром. После загрузки
  аппарат восстанавливается в паузе. Прежние проекты 1–10 открываются.
  Метеоритные сценарии и шар запускаются по отдельности.
- Проверка: npm test, npm run verify:balloon, npm run benchmark:balloon.
  Подробности: verification/BALLOON_REPORT.md.

Лимиты моделей в 0.19.1:
- До 64 МБ на одну GLB-модель или комплект glTF с BIN и текстурами.
- До 512 МБ уникальных моделей на мир, включая переносимый файл .terrain.

Отдельное хранение моделей в 0.19:
- Импортированные GLB хранятся отдельными Blob в IndexedDB. Документ мира,
  автосохранение и история содержат только метаданные и SHA-256 ссылки.
  Одинаковые данные моделей используются совместно разными мирами и копиями.
- До 64 МБ на модель и до 512 МБ уникальных моделей на мир; до 20 моделей,
  64 частей и 100000 вершин на модель. Для glTF лимит входных файлов — 64 МБ.
- «Сохранить проект .terrain» создаёт один переносимый бинарный файл:
  документ мира и все его GLB без Base64. «Загрузить проект» принимает
  .terrain и прежние .json. JSON с одними ссылками требует локальной библиотеки.
- Старые проекты 1–9 открываются, встроенные модели проверяются и переносятся
  в отдельное хранилище. Библиотека обновляется с версии 1 до 2 без сброса
  миров. Сохранённая старая запись заменяется после успешного преобразования.
- Начиная с формата 10, модели хранятся по ссылкам. Ошибка, нехватка места или повреждённая модель
  не заменяет текущий мир частично. Для истории ресурсы сохраняются независимо
  от удаления записи мира; автоматической очистки неиспользуемых GLB нет.
- Проверка: npm run verify:assets, npm run preview,
  /asset-storage-check.html. Тестовая библиотека изолирована.
  Подробности: verification/ASSET_STORAGE_REPORT.md.

Единое создание миров в 0.18:
- Раздел «Миры»: «Создать», «Мои миры», «Обработать». Генерация,
  дополнительная эрозия, локальные биомы и композиция находятся внутри
  ручной обработки. Вместо четырёх отдельных шагов — выбор пресета,
  сида и размера, затем «Создать мир». Предыдущий мир сохраняется отдельно.
- Шесть рецептов: Архипелаг, Пустыня, Тайга, Железные Острова, Фьорды,
  Джунгли. У каждого собственные формы рельефа, растения, поверхность,
  вода, погода и свет. Добавлены 13 локальных моделей с тремя LOD.
- «Показать эскиз» вычисляет карту 64×64, не меняя проект или историю.
  Эскиз показывает макроформу до эрозии. Можно настроить рецепт подробнее:
  высоту, остроту, масштаб, изгибы, силу обработки, растения и маршруты.
- Рельеф и автоматическая эрозия выполняются одним Web Worker с общей
  шкалой прогресса и отменой. Между этапами нет промежуточной загрузки
  сетки на GPU. Кэш хранит не более четырёх карт высот. Для расстановки
  новых миров используются сухие ячейки, исключая бессмысленные попытки
  над морем. Точки прогулки освобождаются от объектов. Маршруты проходят
  по связной суше и не соединяют острова искусственными перемычками.
- Проект формата 9 хранит тип мира и версию рецепта с сидом и опциями.
  Форматы 1–8 загружаются; созданные ранее миры не перегенерируются.
  Старые четыре пресета доступны в ручной обработке.
- Проверка: npm run verify:worlds, npm run preview,
  /world-studio-check.html. Проверочная библиотека изолирована.
  Подходы, источники и результаты: verification/WORLD_STUDIO_REPORT.md.

Туман и непрерывная облачность в 0.17.1:
- Туман воздействует на небо при любой ненулевой плотности. Возле горизонта
  оптический путь длиннее: дальняя вода и небо плавно сходятся в цвет тумана,
  без яркой полосы. Звёзды также затухают к горизонту. Нулевое значение
  отключает эффект; при 200% сохраняется видимость около 3–4 м.
- Вместо конечной облачной плоскости используется непрерывный сферический
  слой в шейдере неба. Он виден за границами карты и с высоты; отражения
  и освещение окружения используют ту же облачность. Отключён второй,
  независимый слой облаков из Three.js Sky. Дальние детали фильтруются.
- На уровне земли облака рисуются вместе с небом. При полёте над слоем
  или рядом с проходящими сквозь него вершинами включается наложение
  с проверкой глубины: облака закрывают дальнюю землю и воду.
  В плотном тумане невидимые детали не вычисляются; обновление карты
  окружения ограничено по частоте. Края отражений воды смешиваются плавно.
- Проверка: npm run verify:fog, npm run preview, /fog-check.html.
  Контрольный мир открывается в отдельной IndexedDB. Отчёт:
  verification/FOG_CLOUD_REPORT.md.

Графика в пределах прежних бюджетов в 0.17.0:
- Согласованы солнечный свет, освещение от неба, цвета атмосферы и растений.
- Новые асимметричные сосны, ели, берёзы, дубы, кусты и камни используют
  не больше треугольников, чем прежние модели. Габариты деревьев сохранены,
  чтобы положение ствола и его коллизия в старых мирах совпадали.
- Дальние модели сохраняют высоту, ширину и палитру ближних. У деревьев
  теперь не больше двух частей на каждом LOD; куст использует одну.
- Переработаны восемь бесшовных текстур земли: подстилка с листьями,
  песчаная рябь, слои скалы, мелкие камни, почва и мох. Размеры 128×128,
  число слоёв и объём данных текстур прежние. Мелкие детали запекаются один
  раз при запуске; в шейдере земли сокращены вычисления процедурного шума.
- Оттенки природных объектов устойчивы при сохранении и смене LOD.
  Новая расстановка дополнительно варьирует пропорции растений и камней;
  эти реальные масштабы сохраняются и учитываются физикой. Алгоритм
  расстановки — версия 5; готовые объекты старых проектов не перегенерируются.
- Повторяемая проверка: npm run verify:graphics, npm run preview,
  /graphics-check.html. Отдельная IndexedDB не затрагивает библиотеку миров.
  Отчёт: verification/GRAPHICS_REPORT.md.

Ускорение ударов по земле в 0.16.2:
- Rapier использует структурированную карту высот с теми же треугольниками,
  что и изображение. Удар обновляет высоты без создания физического мира заново.
  Незатронутые коллизии моделей и состояние плавающих предметов сохраняются.
- Контактное затемнение земли обновляется локально и переиспользует границы
  объектов. История удара не создаёт вторую полную копию проекта.
- Шейдеры вспышки и ударного кольца заранее готовятся во время полёта.
- На сетке 512 с 3000 деревьев медиана CPU-расчёта последствий одного удара
  сократилась примерно с 495 до 36 мс; обновление коллизий — с 430 до 4,4 мс.
  Эти числа относятся к вычислениям, а не к полному времени кадра с рендером.
- 211 тестов пройдены, включая точность поверхности, склоны, мосты, плавание,
  отмену, откат ошибок и совпадение локального затемнения с полным расчётом.
  Отчёт: verification/IMPACT_PERFORMANCE_REPORT.md. Повторение CPU-замера:
  npm run benchmark:impact. Пример: examples/impact-forest.json.

Ускорение Армагеддона в 0.16.1:
- Один постоянный источник света для самого заметного метеорита/взрыва:
  новые падения больше не меняют число источников и шейдеры всей сцены.
- Дым и искры обновляются один раз на кадр и не повторяются в буферах воды.
  Расчёт движения и ударов остаётся с фиксированным шагом 1/120 с.
- После удара пересоздаются только затронутые участки деревьев и травы.
  Восстановление травы распределено по кадрам. Убрано полное обновление
  интерфейса на каждом ударе. Сиды, размеры, кратеры и отмена сохранены.
- В повторяемом браузерном прогоне: самый длинный кадр 590 → 188 мс,
  CPU p95 47,6 → 14,9 мс, число шейдерных программ 105 → 25.
  Результат зависит от мира и компьютера; это замер одного побережья.
  Отчёт и исходные данные: verification/ARMAGEDDON_PERFORMANCE_REPORT.md.

Прибой, свободные руки и Армагеддон в 0.16:
- Убрать предмет: клавиша 0, кнопка «Убрать» на панели прогулки или в инвентаре.

Управление генерацией в 0.14.2:
- «Острота гор» теперь имеет диапазон 0–5: 0 — ровная равнина, 1 — холмы,
  2–3 — горные массивы, 4–5 — крутые склоны и острые вершины.
  При включённом острове сохраняется переход от плоской суши к воде и дну.
- «Высота, м» — верхний бюджет подъёма над равниной, а не растяжение результата
  до одинакового максимума. 0 тоже даёт равнину. Равнина расположена на 3 м
  выше уровня воды. Острота и доля гор определяют использование бюджета высоты.
- «Доля гор» показывается в процентах: от низких холмов без гор до горных
  областей по всей суше. Увеличение доли не уменьшает существующие горы.
- «Масштаб» увеличивает размеры форм по горизонтали; «Искажение» изгибает
  хребты и долины. Эти параметры не перенормируют вертикальную высоту.
- «Октавы» добавляют мелкие детали, сохраняя крупные формы. Диапазон ползунка
  учитывает сетку, площадь и масштаб, поэтому недоступных деталей на нём нет.
- Все параметры применяются кнопкой «Сгенерировать». Сид повторяет мир при
  тех же параметрах; сохранённые проекты загружаются со своим готовым рельефом.
  Горный пресет настроен на остроту 4,2. Версия алгоритма генерации — 6.
- Прошли 181 тест, strict TypeScript, обычная и автономная сборки, проверка
  ползунков и точного результата Web Worker в браузере.

Обычный запуск без интернета и без установки Node.js:
  Двойной клик по terrain_editor_standalone.html.
  Three.js, Rapier с WASM, модели, карты материалов, стили и Web Worker
  встроены в этот файл. После установки запуск не требует сети.
  Природный звук синтезируется локально через Web Audio, внешние аудиофайлы
  не требуются. Первое нажатие клавиши или клик разрешает воспроизведение.

Запуск сборки через локальный сервер:
  start_server.bat — открывает dist/terrain_editor.html на localhost:8080.
  Использует Python, а при его отсутствии — PowerShell.
  Для переноса на другой компьютер достаточно папки dist.

Разработка (Node.js 22.12+; проверено на Node.js 24):
  cd terrain_editor
  npm ci
  npm run dev
  Адрес: http://127.0.0.1:5173
  Можно также запустить start_dev.bat после установки зависимостей.
  Интернет нужен при первоначальной установке пакетов. Приложение не использует CDN.

Проверка и сборка:

Сценарии прогулки:
  В прогулке нажмите «Сценарии» → «Падение метеорита» → «Запустить».
  Размер, точка в небе и направление случайны; подсказка показывает направление
  и расстояние. Дым, грохот, вспышка, выброс частиц и ударное кольцо сопровождают
  удар. Кратер с валом и размер разрушений зависят от размера метеорита.
  Горят деревья, кусты, древесина, мосты, домики и причалы. После затухания
  остаются обугленные объекты. Каменные модели не загораются. В воде — всплеск
  и кратер на дне, без пожара; дождь ускоряет затухание огня.
  Меню, инвентарь, фоторежим и потеря фокуса приостанавливают сценарий.
  «Завершить сценарий» убирает текущие эффекты. Кратер, покраска и повреждения
  сохраняются в проекте и автосохранении. Ctrl+Z в редакторе отменяет весь удар
  одним шагом; Ctrl+Y восстанавливает последствия, без повторного проигрывания.
  Полёт и пламя не сохраняются; загрузка, отмена или редактирование мира завершают
  текущий сценарий. Новый запуск доступен после завершения предыдущего.
  Частицы используют фиксированные буферы: 360/840/1520 мест для экономного,
  сбалансированного/высокого профиля; одновременно видны до 10/20/32 очагов.
  Рельеф обновляется в прямоугольнике удара; коллизии перестраиваются после него.

Отражения в воде:
  «Качество графики» → «Отражения в воде». Та же настройка есть в меню прогулки (Esc).
  Снятие галочки сразу отключает отражения сцены, неба и солнечные блики,
  освобождает текстуру отражения. Настройка сохраняется с миром.
  Экономный профиль при включённой галочке отражает только небо, остальные —
  также сцену. Старые проекты открываются с включённой галочкой.

HUD:
  FPS и «Кадр» измеряют реальный интервал между кадрами, включая задержки.
  Движение рассчитывается с фиксированным шагом 1/120 с, камера интерполируется.
  Обычные кадры при низком FPS догоняют физику; паузы длиннее секунды ограничиваются,
  а потеря фокуса сбрасывает накопленное время и нажатые клавиши.
  При возвращении из фоновой вкладки начинается новый интервал измерения.
  «Объекты» — видимые объекты сцены с учётом экземпляров деревьев и камней;
    это не число объектов, реально попавших в кадр после отсечения камерой.
  «Вызовы» и треугольники учитывают все проходы кадра, включая тени
    и обновление карты окружения. Значения усредняются за ~0,5 секунды.
  «Чанки» — участки рельефа и объектов в текущем поле зрения / общее число.
  Дополнительные статистики terrain, vegetation, foliage и audio доступны
  через window.terrainEditor.statistics.

Формат проекта 10:
  Сохраняет карты высот и покраски, точные объекты с ID и преобразованиями,
  биомы, маршруты, водоёмы, отдельные сиды операций и журнал их параметров,
  настройки прогулки, текущую позицию/скорость и камеру возврата в редактор.
  Float32-высоты записываются явно в формате little-endian.
  Дополнительно сохраняет вторую карту покраски, импортированные GLB и настройки
  мелкой растительности. В JSON находятся ссылки на модели; полный файл
  .terrain содержит документ и двоичные GLB и переносится между компьютерами.
  Также сохраняет влажность, выраженность полян, профиль графики, экспозицию,
  контактное затемнение и громкости звука. Старые файлы версий 1–9
  преобразуются при загрузке; следующие сохранения — версия 10.
  Файл целиком проверяется до изменения сцены: версия, размеры, base64, конечные
  числа, диапазоны настроек, ID, типы объектов, точки маршрутов и состояние прогулки.
  Модели проверяются и разбираются до изменения сцены. JSON-документ — до 32 МБ;
  полный .terrain дополнительно включает до 512 МБ двоичных моделей.
  Ошибка загрузки сохраняет текущий мир и обе очереди истории.

Сиды:
  «Сид» управляет генерацией рельефа и начальными сидами остальных операций.
  В разделе «Сиды операций» можно отдельно задать эрозию, расстановку и шум кисти.
  Одинаковые исходный рельеф, сид и параметры дают одинаковый результат.
  Повторная эрозия поверх уже изменённого рельефа продолжает размывание.
  Журнал хранит последние 10000 процедурных операций с версией алгоритма.

Общая история:
  Ctrl+Z / Ctrl+Y и кнопки отменяют рельеф, покраску, настройки, сиды,
  расстановку, создание/изменение/удаление объектов и загрузку проекта.
  Один мазок или движение ползунка — одна операция. История хранит до 30 шагов.
  При ошибке многоэтапная операция откатывается целиком.
  История живёт в текущей сессии; файл проекта сохраняет состояние мира и журнал
  процедурных операций, а не очередь отмены из предыдущей сессии.

Данные мира:
  «Объекты мира» позволяет изменять X/Z, высоту над землёй, поворот и масштаб,
  удалять их и проверять отмену. Расстановка хранится как точные объекты.
  Раздел «Биомы» позволяет добавить круглый биом в центре вида редактора.
  Маршруты и локальные водоёмы сохраняются и учитываются в распределении;
  их графические инструменты создания относятся к следующим этапам.
  Через window.terrainEditor.worldActions доступны addObject/updateObject/removeObject,
  replaceWorld, setSeeds, setWalkSettings, setPreferences. Изменения входят в историю.
  Карты высот PNG 16 бит и экспорт OBJ поддерживаются.

Новые модули:
  physics.ts    — фиксированный шаг, симуляция ходьбы/плавания/прыжка
  world.ts      — типы объектов, биомов, маршрутов, водоёмов и настроек
  project.ts    — формат 8, проверка и миграция файлов, снимки мира
  operations.ts — сохранение сидов и параметров процедурных операций

Фоновые вычисления (задача 9):
  Генерация, включая смену сетки и случайного сида, и оба вида эрозии
  выполняются в отдельном Web Worker. Во время работы отображаются процент
  выполнения и кнопка «Отменить операцию»; Esc тоже отменяет вычисление.
  До завершения операции сцена содержит исходный рельеф. Результат применяется
  целиком одним действием истории. Отмена завершает Worker и восстанавливает
  прежние параметры, сиды, покраску, объекты и журнал без лишнего шага отмены.
  На каждую операцию создаётся новый Worker; запоздалые сообщения игнорируются.
  Браузер должен поддерживать Web Workers. При ошибке поток не заменяется
  тяжёлыми вычислениями на основном потоке: показывается сообщение об ошибке.
  generateAll() и runErosion() теперь асинхронны: await возвращает true при успехе,
  false при отмене или занятости. window.terrainEditor.ready сообщает о готовности
  после восстановления сессии или начальной генерации.

Автосохранение и библиотека (задача 10):
  Проекты и PNG мини-карты хранятся в IndexedDB текущего браузера.
  Последняя сессия автоматически восстанавливается при запуске, включая камеру
  и положение в прогулке. Применяется та же полная проверка формата проекта.
  После правок запись начинается через 1,5 секунды; положение камеры/прогулки
  проверяется каждые 15 секунд. При скрытии вкладки и выходе выполняется попытка
  немедленного сохранения. Завершение последней записи при резком закрытии
  браузера не гарантируется — ориентируйтесь на надпись «Сохранено».
  Незавершённый мазок, движение ползунка и фоновые операции не записываются.
  Отмена/повтор тоже запускают автосохранение. Новые правки во время записи
  остаются ожидающими и сохраняются следующей записью.
  «Сохранить сейчас» записывает текущий мир, «Сохранить копию» создаёт отдельный
  проект, «Новый мир» сохраняет текущий и генерирует следующий со случайным сидом.
  Название можно изменить в поле над кнопками. В карточках есть дата и превью.
  Открытие мира из библиотеки сбрасывает историю текущей сессии, чтобы отмена
  не переносила изменения между разными проектами. Импорт JSON остаётся отменяемым.
  Активный мир нельзя удалить: сначала откройте другой. Удаление не имеет корзины.
  Сохранение проекта и указателя последней сессии выполняется одной транзакцией;
  при ошибке записи предыдущая версия сохраняется. Ошибки доступа и нехватки
  места видны в панели; экспорт/импорт JSON продолжают работать.
  Повреждённая сохранённая сессия не перезаписывается автоматически. Можно
  открыть другой мир или создать новый, чтобы продолжить автосохранение.

  Библиотека привязана к браузеру и адресу (протокол, имя хоста, порт).
  localhost:8080, 127.0.0.1:4173 и file:// имеют разные хранилища.
  Для стабильного восстановления используйте start_server.bat и один браузер.
  Поддержка IndexedDB у file:// зависит от браузера; при ограничениях запустите
  локальный сервер. Он не требует интернета. Очистка данных браузера удаляет
  библиотеку, поэтому для переноса и резервных копий используйте экспорт JSON.

Отдельный режим прогулки (задачи 11–13):
  P — войти в прогулку или вернуться к сохранённому виду редактора.
  Панель редактирования и подробный HUD скрываются. Вверху остаются кнопки
  автопрогулки, настроек и выхода, внизу — короткая строка управления.
  WASD/стрелки — идти, Shift — бег, Пробел — прыжок, мышь — обзор.
  Клик по сцене запрашивает захват мыши; если он недоступен, обзор работает
  перетаскиванием с зажатой левой кнопкой. Esc открывает меню и освобождает мышь.
  В меню движение и гравитация приостановлены. «Продолжить прогулку» или Esc
  закрывают меню. «В редактор · P» всегда возвращает панель и прежний вид.
  При закрытой боковой панели клавиши генерации, кистей и отмены редактора
  в прогулке не действуют.

Панель редактора во время прогулки (версия 0.7.2):
  Кнопка «Панель · E» или E открывает обычную боковую панель на фоне сцены.
  Персонаж остаётся в режиме прогулки на том же месте; движение, прыжки,
  автопрогулка и обзор приостановлены, мышь освобождена для работы с полями.
  Параметры применяются сразу, изменения сохраняются в истории и проекте.
  В открытой панели работают Ctrl+Z / Ctrl+Y, Tab перемещает фокус по полям.
  «Продолжить прогулку · E», E или Esc закрывают панель и возвращают управление.
  E не мешает вводу текста и чисел. Для обзора снова кликните по сцене.
  Esc при закрытой панели открывает прежнее меню, P выходит в редактор.

Выбор точки старта:
  В разделе «Камера» нажмите «Выбрать точку старта», затем кликните по местности.
  Зелёный маркер — можно начать, красный — показана причина отказа.
  Проверяются сухая площадка под ногами (запас над водой 0,3 м), уклон до 35°,
  отступ от края мира и пересечения тела с габаритами деревьев/камней.
  Габариты учитывают поворот, масштаб, высоту и привязку объектов к рельефу;
  используются консервативные объёмы и пространственный индекс.
  Скрытая расстановка не блокирует старт; ручные объекты проверяются всегда.
  Неудачный клик не изменяет рельеф и не начинает прогулку. Esc отменяет выбор.
  P ищет ближайшую безопасную площадку рядом с ранее выбранным стартом или
  центром вида. Если подходящего места нет, редактор остаётся открытым.
  Координаты выбранного старта сохраняются в проекте и автосохранении.

Настройки управления:
  В меню прогулки доступны чувствительность мыши (0,0001–0,02 рад/пиксель),
  скорость ходьбы (0,1–30 м/с), угол обзора (45–110°) и покачивание камеры.
  В панели редактора остаются дополнительные параметры: бег, высота глаз,
  сила прыжка. Изменения настроек входят в историю и сохраняются в проекте.
  FOV применяется в прогулке; при выходе возвращается обзор редактора 55°.
  Проекты прежних версий открываются с FOV прогулки 70°.

Автопрогулка:
  R или кнопка «Автопрогулка» включает движение вперёд без удержания W.
  Направление меняется вместе с обзором; скорость использует настройки ходьбы.
  R, WASD/стрелки, меню, освобождение захвата мыши и потеря фокуса останавливают
  автопрогулку. Она также останавливается перед водой, крутым склоном,
  препятствием или границей мира. После восстановления проекта движение
  не запускается автоматически — включите его явно.
  При ручной ходьбе столкновения также обрабатываются через Rapier.

Столкновения Rapier (задача 14):
  Персонаж — кинематическая капсула. Физика работает с шагом 1/120 с.
  Рельеф имеет коллизию по треугольникам, деревья — по стволу,
  камни и брёвна — выпуклый объём, мосты — точную коллизию по геометрии.
  Можно подниматься по уклонам до 40°, скольжение начинается с 45°,
  автоматический подъём на ступень — до 0,4 м, прижатие к земле — до 0,3 м.
  Мост с пандусами позволяет войти на настил без прыжка.
  Коллизии пересоздаются после изменения рельефа, объектов, воды и высоты глаз,
  а также после загрузки, отмены и повтора. Скрытые деревья не блокируют движение.
  Кусты и мелкая растительность декоративные и не мешают ходьбе.

Библиотека моделей (задача 15):
  Девять встроенных авторских GLB: сосна, ель, берёза, дуб, куст,
  камень, валун, бревно и мост. Расстановка смешивает деревья разных видов
  и добавляет кусты; старые сохранённые расстановки остаются точными.
  В разделе «Библиотека моделей» выберите модель и нажмите
  «Разместить выбранную модель» — объект появится в центре вида редактора.
  Настройте положение, высоту, поворот и масштаб в «Объектах мира».
  Перед импортом выберите категорию: она определяет размер и вид коллизии.
  Для .gltf выберите одним действием основной файл, BIN и все текстуры.
  Ресурсы с одинаковыми именами неоднозначны; сетевые адреса не загружаются.
  Модели нормализуются по размеру и упаковываются в самостоятельный GLB.

  Draco, Meshopt и KTX2. Лимит модели: 64 МБ, 64 части и 100000 вершин;

Материалы поверхности (задача 16):
  Восемь смешиваемых слоёв: трава, скала, песок, снег, лесная подстилка,
  почва, гравий и мох. У каждого есть локальные карты цвета, микрорельефа
  и шероховатости с mipmaps для уменьшения мерцания вдали.
  Под деревьями автоматически появляется подстилка; склон и высота
  определяют естественное смешивание. Ручная кисть переопределяет смесь.
  «Микрорельеф» регулирует детализацию поверхности; влажность меняет шероховатость.
  Карты создаются программно, внешние текстуры не скачиваются.
  В версии 0.7.1 карты хранятся в независимых слоях DataArrayTexture:
  mipmaps не смешивают соседние материалы, а повторение выполняет GPU
  без разрыва координат на границах плиток. Исправлена светлая сетка на земле.

Мелкая растительность (задача 17):
  Трава, цветы, папоротники и мох создаются воспроизводимо от сида расстановки.
  Участки по 12 м появляются вокруг камеры и удаляются при удалении от неё.
  «Мелкая растительность», плотность и дальность (10–80 м) — в панели
  «Растительность». Одновременно допускается не более 20000 экземпляров.
  У края области используется плавное экранное прореживание, растения качаются
  на ветру. Под водой, на крутых склонах и выше снеговой линии они не создаются.
  На высоте камеры более 35 м над землёй подробная растительность отключается.
  Используются InstancedMesh и общие геометрии; в проекте сохраняются параметры,
  а не тысячи отдельных травинок. Изменение рельефа обновляет участки.

Распределение объектов (задача 18):
  Лесной покров и поляны определяются воспроизводимыми полями от сида расстановки.
  Влажность учитывает общий ползунок, близость воды и низины. Высота и уклон
  ограничивают лес; влажность влияет на породы деревьев, папоротники и мох.
  Кусты появляются преимущественно на опушках, цветы — на лугах и полянах.
  Круглые биомы «Лес», «Луг / поляна», «Побережье», «Горы» имеют плавный край.
  После изменения биомов, влажности и полян нажмите «Расставить растительность».
  Новые объекты не пересекаются с преобразованными габаритами друг друга
  и ручных объектов. Вдоль маршрутов учитываются ширина тропы, габариты модели
  и дополнительный отступ. Мелкая растительность тоже не закрывает тропы.
  Число объектов может быть ниже заданной плотности, если подходящих мест мало.
  Ручные объекты и старые сохранённые расстановки не перемещаются автоматически.
  Новая расстановка использует версию алгоритма 4; она отменяется одним действием.

Чанки и уровни детализации (задача 19):
  Рельеф разделён на участки до 64×64 сегментов. Три LOD используют шаг сетки
  1, 2 и 4 внутри участка, сохраняя все исходные вершины его границы.
  Соседние участки имеют одинаковые высоты и нормали по краям независимо от LOD.
  Кисть принудительно включает полную детализацию редактируемых участков.
  Полная исходная геометрия служит физике, выбору точек, PNG и OBJ:
  изменение детализации камеры не меняет проект или точность столкновений.
  Объекты сгруппированы по участкам 128 м и моделям; каждый участок имеет три LOD.
  Вблизи остаётся исходная модель; вдали деревья и камни заменяются упрощёнными.
  Мосты и брёвна сохраняют геометрию. Порог переключения имеет гистерезис.
  Отсечение выполняется отдельно для камеры и теней: невидимые на экране
  объекты могут продолжать отбрасывать тень. Мелкие растения работают по
  прежним участкам 12 м с лимитом 20000 экземпляров.

Свет и качество (задача 20):
  «Качество графики» находится в редакторе и в меню прогулки.
  Экономный: масштаб пикселей до 0,9, тени и контактное затемнение отключены,
    дальность мелких растений ограничена 25 м, плотность уменьшена вдвое.
  Сбалансированный: масштаб до 1,25, тени 2048, растения до 50 м.
  Высокий: масштаб до 1,75, тени до 4096, растения до 80 м.
  Разрешение теней ограничивается возможностями видеокарты; параметры плотности
  и дальности растительности дополнительно ограничиваются выбранным профилем.
  В прогулке окно теней сосредоточено возле камеры и привязано к шагу пикселя
  карты теней для уменьшения мерцания. В редакторе оно охватывает центр вида.
  Контактное затемнение использует мягкую приближённую карту низин и оснований
  объектов. Карта обновляется после правок и ограничивает частоту пересчёта.
  Общие ACES, экспозиция и корректное преобразование sRGB согласуют материалы.
  Уровни детализации и профиль влияют на отрисовку, не на физику и данные мира.

Погода и окружение (задача 29, версия 0.11):
  Деревья, кусты, трава, цветы и папоротники качаются по общему направлению
  и силе ветра из раздела «Погода». Корни закреплены; фазы зависят от места,
  поэтому растения не движутся синхронно. Нулевая сила ветра останавливает
  движение. Деформация выполняется на GPU для всех LOD; солнечные тени
  используют ту же деформацию. Коллизии стволов остаются неподвижными.

  Дождь и гроза постепенно увлажняют поверхности: земля, камни, растения
  и постройки темнеют, их шероховатость снижается. После дождя остаётся
  влажность, которая высыхает медленнее, чем накапливалась. Её процент
  показывается в «Погода», текущее значение сохраняется в проекте и IndexedDB.
  Это изменение материалов, без расчёта стока воды, луж и намокания под крышей.

  «Туман в низинах» 0–200% создаёт низкий слой в долинах и у берегов,
  учитывая соседние высоты и независимые уровни озёр/рек. Карта плотности
  обновляется после правки рельефа или водоёмов, плавно фильтруется и применяется
  к земле, моделям, растениям и воде. На вершинах слоя нет. Общая «Сила тумана»
  влияет и на него; 0% отключает весь туман. Это недорогая оценка слоя по трём
  точкам луча, без объёмного ray marching. Экономный профиль ослабляет слой.

  «Небо и освещение → Время суток» задаёт условное время 0–24 ч. Свет, цвет
  атмосферы, отражения, облака и звёзды переходят плавно. «Смена дня и ночи»
  включает автоматический цикл; «Длительность суток» задаёт 2–120 реальных минут.
  Часы и положение солнца обновляются в панели. Ручной азимут/высота солнца
  отключают цикл. Пресет также выбирает свой статичный свет; цикл можно включить
  снова. Положение солнца условное, без географической модели и календаря.
  Карта освещения обновляется с ограниченной частотой, а не при каждом кадре.

Фоторежим и любимые точки (задача 30):
  F8 или кнопка «Фоторежим» открывает отдельную камеру из редактора и прогулки.
  Персонаж останавливается. После Esc/F8 восстанавливаются прежняя позиция,
  направление взгляда и режим; открытая панель/инвентарь прогулки возвращаются.
  ЛКМ/ПКМ вращают камеру, колесо приближает, WASD перемещает её, Q/E — ниже/выше,
  Shift ускоряет движение. Кисти и действия прогулки в фоторежиме отключены.

  Доступны угол обзора 15–110°, наклон кадра ±180°, отдельная экспозиция,
  сетка третей и приостановка времени/погоды/ветра/волн. По умолчанию окружение
  приостановлено. Tab или «Скрыть интерфейс» скрывает панель и сетку;
  Tab или компактная кнопка возвращает панель. Esc/F8 всегда выходит.
  Экспозиция и объектив фотокамеры не изменяют настройки редактора/прогулки.

  «Сохранить PNG» записывает только изображение мира: без DOM-панелей,
  сетки третей, кисти, контуров маршрутов и манипуляторов объектов.
  Размеры: текущее окно, ширина 1920 или 3840 пикселей; пропорции сохраняются.
  Разрешение ограничивается видеокартой, 4096 пикселями по стороне и 16 Мп.
  После снимка восстанавливается экранный буфер и плотность пикселей.

  Введите имя и нажмите «Сохранить ракурс». Позиция, цель, угол обзора, наклон
  и экспозиция сохраняются в текущем мире. До 64 ракурсов на мир. Выберите
  точку в списке и нажмите «Вернуться к ракурсу»: камера плавно переместится.
  Сохранение и удаление ракурсов поддерживают общую отмену/повтор (Ctrl+Z/Y).
  Они сохраняются в JSON и IndexedDB, остаются после генерации пресета.
  Временная позиция фотокамеры не заменяет позицию персонажа при автосохранении;
  после перезагрузки открывается обычный редактор/прогулка, затем F8 даёт доступ
  к сохранённым ракурсам. Формат 8 мигрирует проекты 1–7 до изменения сцены.

  examples/weather-photo.json — утро после дождя, ветер, низкий туман и три
  готовые точки: домик, река и пещера. Загрузите через «Файлы → Загрузить проект»,
  нажмите F8, выберите ракурс и «Вернуться к ракурсу».
  Скрипт создания примера: verification/build-photo-example.ts.

Лаборатория WebGPU (задача 31, версия 0.12):
- Открыть: раздел «Эксперименты» → «Лаборатория WebGPU» в боковой панели.
- Прямой запуск: npm run dev → http://127.0.0.1:5173/webgpu_lab.html.
- После npm run build: webgpu_lab.html в dist или автономный webgpu_lab_standalone.html
  в корне проекта / dist. Материалы, код и стили встроены; CDN и интернет не требуются.
- Три режима: WebGL/GLSL, WebGL/TSL, настоящий WebGPU/TSL; два размера сцены.
  Мышью можно осмотреть пейзаж; доступны ветер, влажность и анимация.
- «Сравнить все рендеры» создаёт одинаковые ракурсы, прогревает материалы,
  измеряет медиану/p95 завершённых пакетов, считает вызовы/треугольники,
  сравнивает RGB изображений. Есть отмена, экспорт JSON с замерами и PNG.
- Это тест небольшого набора материалов, а не FPS полного редактора. Время
  включает CPU/драйвер/GPU и синхронизацию; накладные расходы указаны в интерфейсе.
- Если native WebGPU недоступен, результат не подменяется WebGL-замером.
  Используйте поддерживающий браузер и localhost/HTTPS; file:// зависит от браузера.
- На Intel UHD проверены все три режима. Результаты и шесть этапов полного
  перехода описаны в verification/WEBGPU_REPORT.md; JSON и изображения —
  verification/webgpu-v012. Текущий редактор продолжает работать на WebGL.
- Формат проекта остаётся 8. Всего прошло 142 автоматических теста и strict TypeScript;
  сборка создаёт автономный редактор и автономную лабораторию отдельно.
